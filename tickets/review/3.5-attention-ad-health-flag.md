## What shipped

`flag_accounts_needing_attention` gained `include_ad_health: bool = False`. When `True`, AFTER the
flagged list is finalized (behavior flags + optional pacing flag, severity ≥ medium), it fans out
(`fan_out_accounts`) into the ads of **only the flagged accounts** and attaches 0–2 ad-level flags per
account. Off by default → **zero** ad reads (hard regression guard). The opt-in is threaded through the
MCP discovery wrapper and documented in the tool description.

### Engine (`account_discovery.py`)
- **Local status vocabulary** (import-light — no `import monitor`), added near the other attention
  constants:
  - `_AD_DELIVERING = {"ACTIVE", "IN_PROCESS"}` (comment marks it as mirroring `monitor.DELIVERING`).
  - `_AD_PAUSE_STATUSES = {"PAUSED", "CAMPAIGN_PAUSED", "ADSET_PAUSED", "DELETED", "ARCHIVED"}`.
  - `_AD_NOT_DELIVERING_EXCLUSIONS = _AD_DELIVERING | _AD_PAUSE_STATUSES | {"DISAPPROVED"}` (the
    residual-exclusion set for `ads_not_delivering`).
  - `_AD_HEALTH_FIELDS = ["id", "name", "status", "effective_status", "issues_info"]`.
- **`AttentionThresholds.ad_health_min_count: int = 1`** (field + `.defaults()`; a count knob, not a
  percent knee — a flag fires only when its count ≥ this).
- **`_ad_health_flags(ads, thresholds) -> list[dict]`** — PURE, no reader. Returns:
  - `ads_disapproved` (**high**) — count of `effective_status == "DISAPPROVED"` (regardless of `status`).
    `detail = "{n} of {total} ads are DISAPPROVED"`.
  - `ads_not_delivering` (**medium**) — count of `status == "ACTIVE"` ads whose `effective_status ∉
    _AD_NOT_DELIVERING_EXCLUSIONS` (catches `WITH_ISSUES` / `PENDING_REVIEW` / `PENDING_BILLING_INFO` /
    `PREAPPROVED` / future block statuses; a DISAPPROVED ad is counted only by the flag above, never
    double-counted; deliberate pauses excluded). `detail = "{n} of {total} ACTIVE-configured ads are
    not delivering (blocked/pending)"`.
  - Both use the `_flag` shape with `baseline/delta/delta_pct = None`.
- **Orchestration** in `flag_accounts_needing_attention` — inserted between bucketing and the flagged
  sort, so the re-sort sees the recomputed rank:
  - fan-out over `flagged` account ids only; `read_ads` does
    `list(reader.iter_paginated(f"/{id}/ads", params={"fields": ",".join(_AD_HEALTH_FIELDS), "limit": 200}))`.
  - attach flags to the flagged entry, recompute `severity` + `_sort_rank` (max over all flags), so an
    ad-health high flag can PROMOTE a medium account and the existing sort key reorders it.
  - per-account failures → `errors` tagged `{"stage": "ad_health", ...}` (never fatal).
  - `ad_health_scanned_count` added to the result **only when `include_ad_health=True`** (keeps the
    default output byte-identical to the prereq's shape).

### MCP (`mcp_server.py`)
- `build_discovery_tools` wrapper `flag_accounts_needing_attention` gains `include_ad_health: bool =
  False`, passed through. `thresholds`/`fx_table` remain hidden test-only seams.
- `DISCOVERY_TOOL_DESCRIPTIONS["flag_accounts_needing_attention"]` documents the two flags, the
  flagged-only bounded cost, `ad_health_scanned_count`, and the documented limitation.

## Ordering contract (verify this holds)

behavior flags → pacing flag (if `include_pacing`) → bucket into flagged/informational/clean →
**ad-health fan-out over flagged only → attach → recompute severity → re-sort flagged** → strip sort
keys → assemble result. Determinism: `fan_out_accounts` returns input-ordered results, assembled on the
main thread, so identical inputs → identical output regardless of worker completion order.

## Honest gaps / reviewer attention

- **`issues_info` requested but not consumed.** `_AD_HEALTH_FIELDS` includes `issues_info` (mirrors
  `control.AD_FIELDS`) but `_ad_health_flags` reads only `status`/`effective_status` — counts, not the
  policy reason. `id`/`name` are likewise requested but unused by the flag logic. This is intentional
  per the ticket's field list and leaves room for a future "why disapproved" detail; confirm you're OK
  with fetching a field we don't yet parse (it does add payload weight per ad).
- **Pagination not exercised in-test.** Test stubs return one page; `read_ads` materializes with
  `list(...)`. The real multi-page `iter_paginated` path relies on the reader's own contract (tested
  elsewhere) — no multi-page ad list is asserted here.
- **`ad_health_scanned_count` counts *fanned-into* accounts, including per-account failures** (a failed
  read still cost a request). Confirm this "true read cost" semantic is preferred over a
  successfully-read count. A 0-ad account is counted (it read fine, just has no ads).
- **Determinism under real thread contention** is argued structurally (input-ordered results + main-
  thread assembly) and checked by a double-run, but — unlike the pacing determinism test — there is no
  `time.sleep`-based finish-order stress test specific to the ad-health fan-out. Cheap to add if wanted.
- **Account-id form.** `read_ads` builds `f"/{ad_account_id}/ads"` from the row's `ad_account_id`,
  matching `control.scan_issues`. Assumes that id is the `act_…`-usable form the rest of the module
  passes to the reader — consistent with the codebase, but worth a glance.
- **Documented limitation (by design, not a bug):** a window-over-window clean AND on-pace account with
  disapproved ads is never flagged, so never ad-scanned — its disapprovals stay hidden. A full-fleet
  unconditional disapproval scan is a possible future enhancement, explicitly out of scope.
