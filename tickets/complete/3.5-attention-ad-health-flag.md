## What shipped

`flag_accounts_needing_attention` gained `include_ad_health: bool = False`. When `True`, AFTER the
flagged list is finalized (behavior flags + optional pacing flag, severity ≥ medium), it fans out
(`fan_out_accounts`) into the ads of **only the flagged accounts** and attaches 0–2 ad-level flags per
account (`ads_disapproved` high, `ads_not_delivering` medium). Off by default → **zero** ad reads. An
ad-health high flag can promote a medium account and re-sort the flagged list. `ad_health_scanned_count`
is added to the result only when the opt-in is on. Threaded through the MCP discovery wrapper and
documented in the tool description. See the implement commit (`0a3e6ab`) for the full engine/test detail.

## Review findings

**Verdict: sound implementation; two minor doc/wording fixes applied inline, no major findings.**

### Checked — engine correctness (`account_discovery.py`)
- **Double-counting guard.** A `DISAPPROVED` ad (`effective_status`) is caught by the first branch and
  the `elif` for `ads_not_delivering` is skipped — verified it is counted once, by the high flag only.
  Unit test asserts this directly (`status==ACTIVE` + `DISAPPROVED` → disapproved=1, not_delivering
  excludes it). ✓
- **Pause/deliver exclusions.** `_AD_NOT_DELIVERING_EXCLUSIONS = delivering ∪ pauses ∪ {DISAPPROVED}`
  correctly treats deliberate pauses as intent, not stalls, and catches `WITH_ISSUES` / `PENDING_*` /
  future block statuses as residual. ✓
- **Severity recompute + re-sort.** `_sort_rank`/`severity` recomputed as max over all flags after
  attach, BEFORE the existing `flagged.sort`, so a promotion reorders deterministically. `_sort_delta`
  is left intact (correct — the spend-move tiebreak must survive). ✓
- **Determinism.** `fan_out_accounts` returns input-ordered results assembled on the main thread;
  `flagged_by_id` preserves scope order. Double-run equality test confirms it. ✓
- **Reader thread-safety / fan-out reuse.** `read_ads` closure calls `reader.iter_paginated` from worker
  threads — consistent with the existing `cross_account_spend_summary` / pacing fan-outs. Materializes
  with `list(...)` because `_ad_health_flags` scans twice (len + loop). ✓
- **`AttentionThresholds.ad_health_min_count`** added as a defaulted trailing field → no positional
  construction breaks; `.defaults()` sets it; gating test (`min_count=2`) passes. ✓
- **Output shape guard.** `ad_health_scanned_count` present only when `include_ad_health=True`, so the
  default path stays byte-identical to the pacing-era output. ✓

### Found & fixed inline (minor)
1. **Misleading `ads_not_delivering` detail denominator.** The string read
   `"{n} of {total} ACTIVE-configured ads are not delivering"` where `total = len(ads)` is *all* ads
   (including paused/disapproved), not the count of ACTIVE-configured ads — the plain reading implies
   all `total` ads are ACTIVE-configured. Reworded to `"{n} of {total} ads are ACTIVE-configured but not
   delivering (blocked/pending)"`, keeping `total` semantically consistent with the `ads_disapproved`
   flag's `"{n} of {total} ads are DISAPPROVED"`. Updated the one asserting unit test.
2. **Stale docs.** `docs/META_API_SETUP.md` still said *"Ad-level creative/disapproval detection … is
   parked for a later ticket"* — now false. Replaced with a full description of the `include_ad_health`
   opt-in (flagged-only fan-out, the two flags, promotion, `ad_health_scanned_count`, `stage:"ad_health"`
   errors, and the documented clean-account limitation). Added the matching opt-in paragraph to
   `README.md`, which previously documented only `include_pacing`.

### Checked — not changed (deliberate, confirmed acceptable)
- **`issues_info` / `id` / `name` requested but unused** by the flag logic. Per the ticket's field list;
  leaves room for a future "why disapproved" detail. Adds minor per-ad payload weight — acceptable, not
  worth narrowing now. No action.
- **`ad_health_scanned_count` counts fanned-into accounts including failures** (true read-cost
  semantics). Verified by the read-failure test (`scanned_count == 2` with one failure). Correct choice.
- **Documented clean+on-pace limitation** (disapprovals on a never-flagged account stay hidden) is by

- **No other flag-name enumeration** exists in `src/` (flags are freeform via `_flag`), so nothing else
